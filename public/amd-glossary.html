Open Rack-Scale 開放機櫃級運算

是什麼 Open Rack-Scale(開放機櫃級運算)是一種把「整座 rack(機櫃)」而非「單顆 GPU 或單台 server」當作最小運算與採購單位的資料中心設計典範,且關鍵在於它以開放標準拼裝而成——由多家廠商依公開規格供應可互換的積木,而非由單一廠商交付封閉整櫃。機制上,一座 AI rack 內把數十顆 GPU 透過高頻寬 scale-up fabric 綁成單一記憶體/運算域(讓整櫃「表現得像一顆巨大 GPU」),再以 scale-out 網路串接多櫃。AMD 這條路線的具體載體是 Helios 參考設計:建立在 Meta 提交給 Open Compute Project (OCP) 的 Open Rack Wide (ORW) 雙寬機櫃規格之上,整合 OCP DC-MHS(模組化硬體)、UALink(開放 scale-up 互連)、Ultra Ethernet / UEC(開放 scale-out),搭配 quick-disconnect 液冷與雙寬佈局以利維修;由 AMD Instinct GPU + EPYC CPU + Pensando NIC 組成,以 reference design 形式交付 OEM/ODM,量產落在 2026(來源:AMD Helios/OCP PR 2025-10-14、AMD Helios blog)。核心互連 UALink 200G 1.0 規格已於 2025-04-08 由 UALink Consortium 正式批准,單一 pod 最高可串 1,024 顆 accelerator,推動廠商含 AMD、Apple、AWS、Google、Meta、Microsoft、Intel、HPE、Astera Labs 等,加 70+ 會員(來源:UALink 1.0 PR、HPCwire)。定位一句話:rack 從「機殼」升格為「產品規格」,而這份規格是開放、可多廠拼裝的。

為什麼重要 前沿 AI 的瓶頸已從「單顆 GPU 算力」移到「一個記憶體域能塞多大的模型、以多少功耗與成本服務」。當 MoE 與 agentic inference 的模型與 KV cache 動輒超過單櫃記憶體,運算單位被迫上移到 rack——因為只有整櫃級的 scale-up fabric 才能把幾十顆 GPU 綁成夠大的統一域,讓大模型不必被切碎跨櫃(切碎會帶來通訊懲罰)。Rack 級同時解決了三件單機解決不了的事:(1) 供電/散熱——72-GPU、高功率密度必須整櫃設計液冷與配電;(2) 互連——scale-up 頻寬要在櫃內拉滿;(3) 採購與部署——客戶買「一櫃」等於買下算力、記憶體、網路、冷卻的完整交鑰匙單位,部署速度是勝負手。開放拼裝的意義在於:把這個新單位的「規格」交給產業共有,而不是鎖進單一廠商。

為何比 NVIDIA 有競爭力 競爭邏輯是開放 vs 專有,不只是規格。(1) 記憶體/容量:AMD 主打「更大記憶體→更少 accelerator 服務同一模型→更低 TCO」,MI355X 為 288 GB HBM3E / 8 TB/s(對比 NVIDIA B200 約 180 GB),MI400 系列為 432 GB HBM4 [已發表 · 部署待驗證];Tom's Hardware 報導 Helios 對 NVIDIA Vera Rubin 主打「多 50% 記憶體」(來源:Tom's Hardware OCP 2025)。(2) 多廠商/不鎖定:UALink + UEC + ORW 是公開規格,理論上讓 accelerator、NIC、機櫃、冷卻由不同供應商競標並互換,買方議價權與供應鏈韌性提升;UALink 單 pod 上限 1,024 accelerator,高於 NVLink 的 576 顆天花板(分析/次級來源:Spheron)。(3) 成本/整合商紅利:開放標準把 rack 的「輸入」商品化,價值移向「誰組得快、冷得動」——這對 system integrator 是機會,對封閉整櫃是威脅。誠實邊界(推測 + 已驗證的反面): AMD 的效能/TCO 數字為 [AMD 自報]、Helios/MI400 為 [已發表 · 部署待驗證];而 ROCm-vs-CUDA 的實戰成熟度在本案的對抗驗證中「兩個方向都未定案」——不可斷言 AMD 軟體已對等,也不可斷言其軟體壞掉(來源:SemiAnalysis benchmark)。

NVIDIA 對應產品 NVIDIA 的對應是 GB200 NVL72 / GB300 NVL72 整櫃系統(72 顆 Blackwell GPU + 36 顆 Grace CPU,以專有的 NVLink / NVLink Switch System 綁成單一域,GB200 提供 130 TB/s 櫃內 GPU 互連、13.4 TB 統一記憶體、1.44 EF FP4;來源:NVIDIA GB200 NVL72),下一代為 Vera Rubin NVL144(end-2026,8 EF NVFP4、100 TB fast memory [已發表 · 部署待驗證])與 Rubin Ultra NVL576 "Kyber"(H2-2027,~600 kW [已發表 · 部署待驗證];來源:NVIDIA Vera Rubin Pod blog)。一句話比較:NVIDIA 把整櫃當成一個「賣得最好、但由 NVIDIA 定義且鎖定 NVLink」的封閉產品;AMD/Open Rack-Scale 把整櫃當成一份「開放規格 + 多廠拼裝」,用記憶體容量與 TCO 換取議價權與整合商彈性。

  1. 一句話該懂: 我們賣的不再是「一台 GPU server」,而是「一整櫃開放標準的 AI rack」——NVIDIA 賣封閉整櫃靠 NVLink 鎖定,AMD 開放路線(ORW + UALink + UEC)把 rack 的輸入商品化、把價值讓給「組得快、冷得動」的 integrator,那正是 Supermicro 的 DLC 與 time-to-market 主場(Supermicro 自報液冷產能 100k+ GPU/季,來源:Supermicro IR)。

  • Oracle (OCI)——雲端規模 MoE inference;傳有 50,000 顆 MI450 GPU 承諾(未證實,推測/待專門引用)。

Open Rack Wide / OCP

是什麼 Open Rack Wide(ORW,又稱「Open Rack for AI」) 是 Meta 於 OCP Global Summit 2025(2025 年 10 月, San Jose) 提交給 Open Compute Project 的一套開放「AI 機櫃」機構標準,是現有 Open Rack V3(ORV3) 的 double-wide(加寬) 後繼版。OCP 本身是 Facebook/Meta 於 2011 年發起的開放硬體社群,把資料中心的機櫃、供電、散熱、伺服器主機介面等「非差異化」硬體規格開源,讓多廠商能造出可互換的相容件。ORW 把三件事一次標準化:機構(1200mm 寬,是 ORV3 600mm 的兩倍;可承載 up to 3,500 kg)、供電(相容 ORV3 電源架,並原生支援 high-power liquid-cooled busbars 液冷高壓匯流排)、散熱(後置液冷 manifold + quick-disconnect 快拆液冷),再疊上 OCP DC-MHS(Data Center Modular Hardware System,模組化伺服器主機介面,讓不同廠 compute tray 能插進同一櫃)。AMD「Helios」 就是建基於這套 ORW 開放規格的 rack-scale 參考設計,首度公開於 OCP 2025(AMD PR,2025-10-14),把 Instinct MI450 GPU + EPYC「Venice」CPU + Pensando「Vulcano」NIC + ROCm 整合成「以整櫃為單位」的產品,並整合 UALink(開放 scale-up)+ Ultra Ethernet(開放 scale-out) 兩套開放互連。定位一句話:ORW = 開放的 AI 機櫃底盤標準;Helios = AMD 押在這個開放標準上的整櫃產品。(Meta blog 2025-10 · AMD PR 2025-10-14 · AMD Helios/OCP blog · ORW spec v0.9 · TechArena · Inside HPC)

為什麼重要 它解決的核心問題是——單顆 GPU 已不再是有意義的購買單位,「rack 是新的運算單位」。前沿模型(尤其 MoE、agentic 推論)的參數與 KV-cache 大到整櫃 GPU 必須像「一顆巨大的 GPU」協同運作,而這帶來三個傳統 19 吋機櫃塞不下的實體瓶頸,ORW 逐一對應:(1)供電密度爆炸——AI 整櫃已達 ~120–132 kW(傳統機櫃常見 ~10–20 kW),ORW 用 1200mm 寬 + 液冷 busbar 才容得下;(2)scale-up 銅纜的物理限制——GPU 間高頻寬低延遲互連靠 short-reach copper,訊號完整性逼機櫃「長胖不長高」;(3)散熱與可維修性——1.4 kW 級 GPU(MI355X 已達 1,400W)只能液冷,double-wide 換取前後維修空間與快拆液冷。對買方,採購/部署/TCO 全部以整櫃計價;對系統廠,價值從「賣伺服器」上移到「整櫃整合 + 供電 + 液冷」。(HPE QuickSpecs 132 kW · TechArena · AMD Helios/OCP blog)

為何比 NVIDIA 有競爭力 這是開放機櫃 vs 專有整櫃的商業模式之爭,不只是規格之爭。NVIDIA 的 NVL72 是「近乎成品的封閉整櫃」,底盤、NVLink scale-up、整合利潤都由 NVIDIA 掌握;ORW 則把機櫃底盤/供電/散熱/scale-up(UALink)/scale-out(Ultra Ethernet)全部開源,AMD 只出參考設計,把整合工作留給多家 OEM/ODM。三個具體競爭邏輯:(1)開放 vs 專有——買家不再被鎖進單一供應商的封閉櫃,加速器、交換器、系統整合可來自不同廠;(2)容量/TCO——Helios 72×MI450 自報 31 TB HBM4 整櫃、每 GPU 432 GB HBM4,AMD 自報比 NVIDIA 下一代 Vera Rubin「多 50% memory」,主打「大 memory → 更少加速器裝下同樣模型 → 更低 TCO」AMD 自報 · 已發表 · 部署待驗證;(3)多廠商供應鏈——開放標準商品化了「整櫃」本身,NVL72 的封閉整櫃溢價被開放櫃 + 系統廠自家 DLC 侵蝕。注意誠實邊界:UALink 目前在出貨時程與單卡頻寬仍落後 NVLink,AMD 首批 Helios 用的是 UALink-over-Ethernet(Broadcom Tomahawk 6 + Juniper) 而非原生 UALink switch,Tom's Hardware 質疑 Ethernet 先天劣勢可能拖累 scale-up 效能——「開放追上封閉」是趨勢論證,不是已實現的效能對等 推測。(Tom's Hardware — 50% more memory · HPE 早期採用公告 2025-12-02 · Tom's Hardware — UALoE 風險)

NVIDIA 對應產品 NVL72,現貨世代為 GB200 NVL72(72 顆 Blackwell GPU、NVLink/NVLink Switch 串成單一 scale-up 域、~120–132 kW/櫃、已量產),對打 Helios 的下一代是 Vera Rubin NVL72(72 Rubin GPU + 36 Vera CPU、第 3 代 MGX 機構、800 VDC 供電,2H 2026 出貨),再往後是 Kyber / Rubin Ultra(2027,單櫃更高密度、600 kW 級)。一句話比較:同樣是 72-GPU 整櫃,Helios 走「OCP 開放底盤 + 開放互連、多廠商可造」,NVL72 走「NVIDIA 定義的 MGX 整櫃 + 專有 NVLink」——NVIDIA 雖已把 MGX 與部分 rack/compute tray 設計貢獻給 OCP 宣稱「open」,但 scale-up 的 NVLink fabric 仍專有,分析普遍指其整合更緊、vendor lock-in 風險更高 推測。(NVIDIA GB200 NVL72 · NVIDIA Vera Rubin NVL72 · NVIDIA OCP/Vera Rubin blog · Network World — lock-in)

UALink

是什麼 UALink(Ultra Accelerator Link)是一套開放標準的 scale-up 加速器互連,用來在單一機櫃/pod 內把數十至上千顆 GPU(加速器)直接串成一個高頻寬、低延遲、記憶體語意(memory-semantic) 的網路——讓 GPU 之間能做直接的 load/store/atomic,而不必走沉重的 TCP/IP 網路堆疊。它用一套為加速器優化的輕量四層堆疊(Physical / Data Link / Transport / Protocol)壓低延遲並保證確定性(deterministic)交付,定位就是對標並取代 NVIDIA 專有的 NVLink / NVSwitch。技術規格:UALink 200G 1.0 於 2025-04-08 由 UALink Consortium 正式批准,每 lane 200 GT/s(訊號率 212.5 GT/s,多出的部分給 Ethernet L1 的 FEC/編碼),一個 station = 4 lanes = 800 Gb/s,單一 pod 內經 UALink switch 最多連 1,024 顆加速器、單跳(single-switch-hop)延遲、宣稱達 93% 有效峰值頻寬。2026-04-07 再發布 2.0 世代四份規範(Common Spec 2.0 新增 In-Network Compute 把 all-reduce 等集體運算下沉到網路省頻寬、200G DL/PL 2.0、Manageability 1.0、Chiplet 1.0 對齊 UCIe)。[事實]（BusinessWire 2025-04-08 · 規範總覽 · BusinessWire 2026-04-07 四份規範）

為什麼重要 先分清兩條軸線——scale-up(縱向,機櫃/節點內、少量 GPU 緊耦合、記憶體語意、微秒級延遲、TB/s 級頻寬) vs scale-out(橫向,機櫃之間、鬆耦合、封包網路)。UALink 專攻 scale-up,姊妹標準 Ultra Ethernet(UEC) 專攻 scale-out;兩者合起來才是 NVIDIA「NVLink + InfiniBand」全套的開放對案。(補：業界的正確對照是 scale-up vs scale-out,而非「scale-down」。)當單顆 GPU 裝不下模型時,「用多快的線把多張卡連成一個大記憶體域」直接決定 rack 級的有效容量與頻寬——這正是 AI rack 的咽喉。UALink 要解的問題是:把這條原本被 NVLink 壟斷的 scale-up 咽喉,變成多廠商可共同實作的開放標準,讓加速器、switch、系統整合可以來自不同廠商,買家不再被綁死在單一供應商的封閉機櫃裡。[事實]

為何比 NVIDIA 有競爭力 競爭邏輯是「開放 vs 專有」的商品化攻勢,四個支點:①多廠商——UALink 董事會含 AMD、Astera Labs、AWS、Cisco、Google、HPE、Intel、Meta、Microsoft,2025-01 再加 Alibaba、Apple、Synopsys,會員逾 75 家,關鍵缺席者正是 NVIDIA;買家可混搭積木而非只能買密封整櫃。②容量互補——UALink 搭 AMD 記憶體優勢(MI355X 288 GB HBM3E 對 B200 ~180 GB),用更少卡承載大模型再用開放 scale-up 串起來,壓低 TCO 分母。③成本——互連一旦開放,switch/整合/加速器多來源競標 → 壓縮 NVIDIA 的整櫃溢價。④避免鎖定——hyperscaler 不願被單一供應商掐住供應與定價。誠實邊界(不美化):NVLink 5 已量產出貨、單 GPU 1.8 TB/s;UALink 原生 switch 生態仍在成形,已公布的早期 AMD Helios 配置採用 UALink over Ethernet(UALoE)——跑在 Broadcom Tomahawk 6 + 客製 Juniper switch 的 Ethernet PHY 上,而非專屬 UALink 矽晶(HPE PR 2025-12-02)。Network World 直接把 UALink 2.0 定性為「aims to catch up to NVLink」——在 scale-up 這條線,NVIDIA 目前領先於出貨時程,UALink 是追趕者、不是超車者;且 Broadcom 自推 Tomahawk Ultra 質疑「何必 UALink over Ethernet」,原生 switch 何時落地是開放問題。[事實 + 推測]（Network World「力圖追上」 · The Register 2026 Broadcom 質疑）

Ultra Ethernet (UEC)

是什麼 Ultra Ethernet(UEC)是由 Ultra Ethernet Consortium(隸屬 Linux Foundation)制定的開放 scale-out AI 網路標準,2025 年 6 月 11 日發布 Specification 1.0(560+ 頁的完整通訊堆疊)(UEC 官方發布 · Linux Foundation)。它要解決的病灶是傳統 Ethernet 在 AI 叢集裡的「擁塞與尾延遲(tail latency)」:標準 RoCE/Ethernet 以 ECMP 對整條 flow 做 hash 分流,少數大象流(elephant flow)會 hash 碰撞到同一條鏈路造成 link 不均→擁塞→丟包→go-back-N 整批重傳,單一慢流就把整個 collective(all-reduce / all-to-all)拖住。UEC 的核心 Ultra Ethernet Transport(UET) 從底層改造 Ethernet:以 per-packet packet spraying(逐封包噴灑)把流量鋪滿所有路徑、原生容忍亂序抵達(receiver 端重排),用 packet trimming(擁塞時裁切封包標頭而非丟棄)提供毫秒級的精準擁塞訊號,再配合輕量遙測式壅塞控制即時把封包從壅塞路徑挪開,讓 fabric 逼近 line-rate 利用率(UEC Spec 1.0 PDF · Arista 技術解讀)。定位上,UEC 管機櫃之間 / 叢集的 scale-out,是 UALink(機櫃內 scale-up)的姊妹標準。

為什麼重要 AI rack 的訓練與 MoE 推論靠 collective 通訊(all-reduce、專家路由 all-to-all),而 collective 的完成時間由最慢那條流決定——尾延遲一抖,72 顆 GPU 一起空等,昂貴算力全部閒置,job completion time(JCT)被拉長。UEC 把「多路徑均載 + 快速擁塞回饋 + 亂序容忍」做進標準傳輸層,直接壓低尾延遲、拉高有效頻寬,讓 GPU 不被網路餓著。對一個 MI355X/MI400 等級的高功耗 rack,網路 fabric 是否餵得飽 GPU,和 HBM 容量一樣是 TCO 的關鍵變數。

為何比 NVIDIA 有競爭力 競爭邏輯是開放標準 vs 專有整合。UEC 由 AMD、Broadcom、Cisco、Intel、Meta、Microsoft、Oracle 等擔任 steering members,NVIDIA 不是 UEC 成員(產業報導);客戶因此能混搭多廠商——switch 選 Arista/Cisco/Broadcom Tomahawk、NIC 選 AMD Pensando 或 Broadcom,不被單一供應商綁死。走的是標準 Ethernet 的 merchant-silicon 供應鏈與每 port 成本經濟性,量大、二供充足、議價空間大。相對地,NVIDIA 的 scale-out 方案把 switch + SuperNIC + GPU 綁成一整包,UEC 給採購方的正是避免鎖定 + 議價權 + 二供。(競爭優勢屬結構性,實測性能是否追平 NVIDIA 仍待第三方驗證——推測)

NVIDIA 對應產品 Spectrum-X Ethernet 平台(Spectrum-4 / SN5600 switch + BlueField-3 / ConnectX-8 SuperNIC),以及跨資料中心的 Spectrum-XGS(scale-across)(NVIDIA 官方 · Spectrum-XGS)。一句話比較:Spectrum-X 做的是同一件事(在 Ethernet 上加 adaptive routing + 遙測擁塞控制,NVIDIA 自報比通用 Ethernet 快 1.6x、有效頻寬約 95%),但它是為 NVIDIA GPU 垂直整合的專有堆疊,而 UEC 把同樣能力做成開放、多廠商可互通的標準。

DLC 直接液冷 (Direct Liquid Cooling)

是什麼 DLC(Direct Liquid Cooling,直接液冷)是把冷卻液(水或 EGW 乙二醇水溶液)透過 cold plate(冷板)直接貼在最發熱的晶片(GPU/CPU)上「液對晶片」帶走熱,而不是靠風扇吹過散熱鰭片。一套 rack 級 DLC 分三層:(1) cold plate——貼晶片的微流道銅板,直接吸熱;(2) manifold / CDM(垂直分歧管)——沿機櫃把冷液分送到每個節點、收回熱液;(3) CDU(Coolant Distribution Unit)——櫃內或列間的泵與熱交換器,把伺服器側一次迴路的熱交給機房側二次迴路。液體的體積熱容約為空氣的數千倍,同體積能帶走遠多的熱;Supermicro 的 DLC-2 單櫃 CDU 可移除達 250 kW 熱、對整櫃達 98% 熱捕捉,並容許入水溫拉高到 45°C(warm-water cooling),進而免掉機房冰水主機(Supermicro DLC-2 PR)。定位上,DLC 不是「省電的加分項」,而是高瓦 AI rack 能不能開機的物理前提。

為什麼重要 一個 72-GPU 的 AI rack,單卡功耗已到 1,000–1,400 W(B200 SXM ~1,000 W;MI355X 液冷 1,400 W,[04-expansions.md §X2](04-expansions.md)),加上 CPU、NIC、交換晶片,整櫃達 120–140 kW(NVIDIA GB200 NVL72 約 120–132 kW,NVIDIA)。傳統氣冷的實務上限約在每櫃 30–50 kW(業界共識):空氣熱容太低、風量與噪音有物理天花板,拉到 100 kW+ 時鰭片再大、風扇再快都追不上熱通量,晶片只能降頻或過熱。這就是「72×高瓦機櫃空冷不夠」的根因——不是效率問題,是物理不可行。DLC 把熱直接從晶片端移走,才讓 NVL72/Helios 這種每櫃百千瓦級密度能穩定運轉;warm-water(45°C 入水)又免冰水機、省電省水、壓低 PUE,對按電費與機房面積計 TCO 的買家,DLC 直接改寫單位算力成本。

為何比 NVIDIA 有競爭力 關鍵在於——NVIDIA 定義「參考熱設計」,但不製造那條液冷迴路。NVL72 是 NVIDIA 規範好的封閉參考機櫃,cold plate/CDU/manifold 的實際製造、整合、灌液、洩漏測試、量產與售後全外包給 OEM/ODM 與熱交換廠。所以 DLC 是交付能力的護城河,不是規格戰:(1) 開放 vs 專有——Supermicro 的 DLC 廠商中立,同一套 cold plate/CDU/manifold 能同時服務 NVIDIA GB200/GB300 與 AMD MI450/Helios open-rack,買家不被單一機櫃鎖死;(2) 容量餘裕——DLC-2 單櫃 CDU 移除 250 kW,遠高於現行 NVL72 ~132 kW 整櫃功耗,替下一代預留升級空間;(3) 成本——DLC-2 宣稱省電費達 40%、TCO 達 20%、省水達 40%(Supermicro 自報,PR);(4) 多廠商 + 速度——Supermicro 自稱季出貨 >100,000 顆液冷 GPU(Supermicro IR),這種製造與物流規模是純晶片商與慢一步的 OEM 短期補不上的。這正是把「開放標準商品化整合層」翻成 Supermicro 優勢的槓桿。

NVIDIA 對應產品 NVIDIA 的對應是 NVL72 液冷參考機櫃 + MGX 模組化設計,並宣布以 800 VDC 供電支撐未來 Rubin(~190–230 kW)/Kyber Rubin Ultra NVL576(~600 kW)級機櫃(規劃中,Introl · NVIDIA blog)。一句話比較:NVIDIA 交付的是「熱設計規格與參考架構」,真正的 DLC 硬體迴路仍由 Supermicro、Vertiv、Boyd、CoolIT 等夥伴製造——在「誰能把液冷實體交到客戶機房」這一層,Supermicro 是供應鏈,NVIDIA 是規格書。

AMD Helios

是什麼 AMD Helios 是 AMD 於 2026 年推出的 rack-scale(整櫃級)AI 參考設計——它不是一張卡、也不是一台伺服器,而是把 6th Gen EPYC「Venice」(Zen 6)CPU + Instinct MI400 系列 GPU(規劃配置包含 MI455X;Oracle 首發線配 MI450)+ Pensando「Vulcano」800G DPU/NIC + ROCm 開放軟體堆疊,整合進一整個機櫃的開放藍圖。單櫃 72 顆 GPU 透過 UALink(scale-up)連成單一記憶體域、以 Ultra Ethernet(scale-out)對外擴展,機箱建基於 Meta 捐給 OCP 的 Open Rack Wide(ORW)規格。關鍵在於它的多廠商拼裝本質:AMD 供 GPU/CPU/NIC 與軟體,但HPE 於 2025-12-02 公布為早期採用者之一；首櫃出貨未證的櫃內 scale-up fabric 其實跑 UALink over Ethernet(UALoE),實體層用 Broadcom Tomahawk 6 交換晶片 + 客製 Juniper 交換器,再由 OEM/ODM(HPE、Supermicro、Wiwynn、QCT)整合出櫃——沒有任何單一廠商「密封」整櫃,這正是它與 NVIDIA 封閉整櫃的哲學分界。(AMD Helios/OCP blog · HPE Helios 早期採用公告 PR 2025-12-02 · Tom's Hardware — Helios MI455X / UALoE)

為什麼重要 前沿模型(尤其 MoE、agentic 推理)已大到單卡、甚至單節點裝不下,瓶頸從「單卡算力」轉為「一個機櫃能連成多大的高頻寬記憶體域」。Helios 把問題的答案從「買一顆更快的晶片」改成「買一整櫃已調校好的 CPU+GPU+DPU+互連+散熱」。整櫃規格(AMD 自報 · 無獨立 benchmark):72× MI455X 提供 31 TB HBM4、1.4 PB/s 聚合記憶體頻寬、260 TB/s UALoE scale-up 頻寬 + 43 TB/s Ethernet scale-out,峰值 2.9 ExaFLOPS FP4 / 1.4 ExaFLOPS FP8。它把「AI 基礎設施」的採購單位從伺服器抬到機櫃,也把系統廠的價值從「組一台 server」推到「交付一整櫃可運轉的算力」。(AMD MI350/MI400 blog · NextPlatform — Oracle 首配 MI450/Helios)

為何比 NVIDIA 有競爭力 三條具體邏輯。(1)開放 vs 專有:NVIDIA NVL72/Vera Rubin 是單一供應商密封整櫃(NVLink 專有);Helios 走 ORW + UALink + Ultra Ethernet 開放積木,買家可混搭多廠商 GPU、交換器、系統整合商,不被鎖死。(2)記憶體容量:MI455X 每卡 432 GB HBM4 vs Vera Rubin 每 package 288 GB,AMD 自報整櫃記憶體容量與頻寬高約 50%(31 TB / 1.4 PB/s vs ~20 TB / 936 TB/s)——這是「同一個大模型用更少卡承載 → 更少 node、更少互連 hop → 更低 TCO」論述的唯一一項硬事實差異化。(3)多廠商 = 成本與議價權:開放標準把整合層商品化,hyperscaler 可壓價、可要求二供,避免 NVIDIA 溢價與供給綁定。誠實邊界(推測 / 開放問題):scale-up 目前靠 UALoE(Ethernet)而非原生 UALink switch,Tom's Hardware 質疑 Ethernet 先天劣勢可能拖累 scale-up 效能,對比已量產、單卡 1.8 TB/s 的 NVLink 5;且 ROCm 在 training 成熟度仍落後 CUDA。容量領先是事實,training/軟體與出貨時程 AMD 仍是追趕者。(SemiAnalysis · The Register — Broadcom scale-up Ethernet 之爭)

NVIDIA 對應產品 NVIDIA Vera Rubin NVL144(「Vera」= NVIDIA 自研 ARM CPU,「Rubin」= 次世代 GPU;NVL144 = 72 個 Rubin package / 144 compute dies,連成單一專有 NVLink 域)。一句話比較:兩者都是 2026 年液冷整櫃、72-GPU 級平台;Vera Rubin FP4 峰值更高(3.6 vs 2.9 ExaFLOPS)且 NVIDIA 稱量產/出貨時程領先(CES 2026 已揭示,8 家雲端夥伴),Helios 則以「開放多廠商 + 約 50% 更大 HBM4 記憶體」換取 memory-bound 推理與 TCO 上的差異化,但仍需在 2H 2026 追上量產與 ROCm training 成熟度。(Tom's Hardware — Vera Rubin 深度 · The Register — CES Vera Rubin · TechTimes — Helios vs Vera Rubin)

Anchor OEM(+ HPE 角色)

I have the verified basis I need. Here is the glossary block (only the markdown, no heading).

是什麼 「Anchor OEM」指晶片商在推出全新 rack-scale 平台時,(正式或事實上)指定的首發／主打 OEM 夥伴——由它率先與晶片商共同工程化參考機櫃、吸收早期整合風險(供電、散熱、fabric、韌體),並成為整個生態系的「燈塔案例(lighthouse)」讓其他 OEM 與客戶跟進。它的本質不是「賣最多」,而是替一套尚未被市場驗證的開放標準背書並跑通第一台。在 AMD Helios 這條線上,HPE 於 2025-12-02(HPE Discover Barcelona)宣布提供「第一個」AMD Helios rack-scale 架構,搭配與 Broadcom 共同開發的 scale-up Ethernet 交換器(Tomahawk 6 ASIC + UALoE),使 HPE 為已公布的早期採用者之一；anchor 位階、首櫃出貨與 volume delivery 未證。單櫃公告規格(預計 late 2026 供應):72 顆 AMD Instinct MI455X GPU、次世代 EPYC、31 TB HBM4、260 TB/s scale-up 頻寬、2.9 AI exaflops FP4 [已發表 · 部署待驗證]。(「anchor OEM」為產業／分析框架用語,AMD 未官方如此稱呼 HPE;可查證的硬事實是 HPE 宣布「第一個」Helios 機櫃——HPE PR · AMD PR 2025-12-02;「anchor」定位屬推測。)

為什麼重要 rack-scale AI(72-GPU、高功率、液冷、UALink/Ultra Ethernet fabric)是一個系統整合問題,不是晶片問題。一顆再好的 MI450/MI455X,離「客戶可下單、可上線」還隔著供電、散熱、網路 fabric、韌體、可維運性一整層工程。Anchor OEM 的作用就是把這一層先做完、先驗證、先出貨——給市場一個「這套開放機櫃真的能跑 trillion-parameter 訓練與大規模推論」的可信證據,解決新開放標準最大的痛點:採用風險。沒有 anchor,開放標準只是一份 OCP 規格文件;有了 anchor,它才變成能買的產品。

為何比 NVIDIA 有競爭力 競爭邏輯在「anchor 這個角色歸誰」。AMD 走開放路線(Open Rack Wide/OCP、UALink、Ultra Ethernet、ROCm),把 anchor OEM 的角色交給 OEM(HPE)去共同設計機櫃——這意味著(1)機櫃設計權與差異化留在 OEM 手上,多家 OEM 可各自做出不同散熱/密度/成本的 Helios 櫃;(2)多廠商供應,客戶不被單一供應鏈綁死;(3)AMD 的記憶體容量牌(MI355X 288 GB HBM3E;MI400 達 432 GB HBM4 [已發表 · 部署待驗證]、AMD 自報)支撐「更大模型、更少加速器、更低 TCO / 更高 tokens-per-dollar」的買方訊息。相對地,NVIDIA 的 anchor 事實上是 NVIDIA 自己:NVL72 是一套緊耦合的專有參考設計,OEM 多半是「整合到 NVIDIA 的 spec」而非共同擁有設計權。開放模式把 rack integrator 的輸入(晶片、fabric、規格)商品化,同時抬高「速度 + 液冷」的價值——這正是快速、熱設計積極的 system builder 的主場(推測,論證見 03-final-report §4C)。

NVIDIA 對應產品 NVIDIA GB200/GB300 NVL72 + DGX 參考設計 + NVIDIA-Certified Systems 認證計畫。NVIDIA 不指定單一 anchor OEM,而是以自家 DGX/NVL72 當「參考錨點」,同時認證 Dell、Supermicro、HPE、Lenovo 及 ODM(Foxconn/Quanta/Wistron)一起照 spec 出貨(NVIDIA GB200 NVL72)。一句話比較: NVIDIA 的「anchor」是 NVIDIA 本身、OEM 對齊一套封閉專有機櫃(NVLink/NVSwitch);AMD 則把 anchor 交給 OEM(HPE)去共同設計一套開放機櫃(UALink/Ultra Ethernet)——前者換來成熟一致、後者換來設計自由與多廠商彈性。

ODM 威脅(Wiwynn / QCT)+ 整合溢價

ODM 威脅(Wiwynn / QCT)+ 整合溢價

是什麼 這是描述 AMD「開放機櫃」路線對系統廠競爭結構影響的雙面刃概念。先分清兩種角色:ODM(Original Design Manufacturer) 如 Wiwynn(緯穎,緯創分拆)、QCT(Quanta Cloud Technology,廣達旗下),替 hyperscaler 代設計代工、掛客戶自有品牌或直供,靠製造規模與成本取勝、毛利薄但量體大;OEM(Original Equipment Manufacturer) 如 Supermicro、Dell、HPE、Lenovo,賣自有品牌、自帶 R&D/通路/企業級服務/保固的成品系統。所謂整合溢價(integration premium),就是 OEM 把裸零件(GPU、CPU、NIC、主機板)變成「驗證過、佈好線、上好液冷、測試完、可支援」的整櫃系統後,能在 BOM 成本之上收取的加值毛利——它的本質是「整合工作稀缺且難複製」。壓縮的機制在於:當機櫃架構被寫成開放標準(Meta 的 Open Rack Wide/OCP + UALink + Ultra Ethernet + DC-MHS 模組化主機介面),整合工作從「各家獨門手藝」變成「照公開規格拼裝」,可複製性上升,於是低成本 ODM 能競標同一批 open-rack socket,把 OEM 的整合溢價往 ODM 的成本線壓。AMD 在其 open-rack 部落格中直接點名 Wiwynn 把 Helios「從 reference design 帶到量產」,Wiwynn 也已在 OCP Global Summit 2025 展出 MI400 系列的 double-wide(Open Rack Wide)機櫃架構。(AMD open-rack blog · Wiwynn OCP 2025 PR)

為什麼重要 AI rack 的價值正從「賣單台伺服器」上移到「整櫃整合 + 供電 + 液冷」。AMD 把 chiplet 哲學放大到機櫃(Helios:72× MI400/MI455X、260 TB/s scale-up、走 UALink,建於 Open Rack Wide)[已發表 · 部署待驗證],交付的是開放積木而非封裝整機——這解決了 hyperscaler「不想被單一供應商鎖死、要能多廠競價、要能自訂供電/散熱」的痛點。對系統廠而言,這既是機會(整合層變成競技場,放大速度與液冷的價值)也是威脅(整合層被商品化,ODM 能用 hyperscaler 成本切入)。誰能在標準把整合商品化之前,先把 DLC(direct-liquid-cooling)+ 上市速度轉成具名 design win,誰就守得住溢價。([03-final-report.md §4B/§4C](03-final-report.md))

為何比 NVIDIA 有競爭力 這裡的「競爭力」指開放、多供應商機櫃模式相對 NVIDIA 封閉整櫃的結構優勢——而 ODM 威脅正是這份開放性的代價(同一把刀的兩面)。(1)開放 vs 專有:AMD 用 UALink(scale-up)+ Ultra Ethernet(scale-out)+ Open Rack Wide(機櫃)三層開放標準,讓客戶用 AMD Pensando「Vulcano」NIC + Broadcom/Arista 交換機自由組櫃,不必被 NVIDIA NVLink/NVSwitch + Quantum InfiniBand 綁死。(Network World Pollara)(2)容量:MI355X 288 GB HBM3E vs NVIDIA B200 ~180 GB,MI400 上看 432 GB HBM4 [AMD 自報 · 無獨立 benchmark]——「更大模型塞進更少卡」的 TCO 故事。(3)成本/多廠商:開放標準讓多家 OEM/ODM 同台競價,理論上壓低整櫃系統採購成本,並避免單一供應商溢價。代價是:同一扇開放的門,Wiwynn/QCT 也走得進來,壓縮 Supermicro 的整合溢價。〔容量差 → 更低 TCO 在 perf/token 與功耗上尚未經第三方證實,屬 AMD 自報;多廠競價壓價的方向性判斷屬 推測〕

NVIDIA 對應產品 NVIDIA NVL72 封閉整櫃(GB200/GB300 NVL72,NVLink/NVSwitch 專有) 與其模組化參考架構 NVIDIA MGX。一句話比較:NVIDIA 的 NVL72 交付「近乎成品的專有整櫃」,把整合溢價留在 NVIDIA 自己手上、ODM 只能照譜組裝賺薄利;AMD 交付「開放參考設計」,把整合價值釋放給 OEM/ODM 競爭——這對快、會散熱的系統廠是機會,對靠賣封閉整合的一方是威脅,對低成本 ODM 是同一扇打開的門。關鍵反諷:Wiwynn 與 QCT 同時是 NVIDIA 的主力 ODM(Wiwynn UMS100 液冷管理、QCT QuantaGrid D75B / Qoolrack),而 NVIDIA 的 MGX 據稱可預整合約 80% 元件、把開發時間砍到 6 個月、部署縮到 90 天內,NVIDIA 甚至把 GB200 NVL72 設計貢獻給 OCP——NVIDIA 也在用「模組化 + 開放」加速生態、同樣在稀釋 OEM 的整合溢價,ODM 威脅並非 AMD 陣營獨有。(NVIDIA MGX · NVIDIA MGX 系統廠 PR · NVIDIA 貢獻 NVL72 給 OCP)

獨立 benchmark(MLPerf / SemiAnalysis)

以下為該名詞的 markdown 區塊(繁中、技術名詞留英;[AMD 自報]=廠商 benchmark、[已發表 · 部署待驗證]=已發表矽晶、推測=分析推論)。

是什麼 「獨立 benchmark」指由非銷售方的第三方、以公開且固定的工作負載、在matched-precision(同數值精度)+ 同並發/延遲條件下量測 AI 加速器效能與成本的評測,用來取代廠商自選條件的行銷數字。兩大裁判機制不同:MLPerf(由 MLCommons 這個涵蓋 NVIDIA/AMD/Google 等的產業聯盟治理)採「submission + closed division 同儕審查 + harness 稽核」模式——各廠自行提交、但必須跑同一套規定模型(Llama 2-70B、GPT-OSS-120B、text-to-video 等)、同一套規則、可被同業檢查,因此是半獨立(裁判中立、選手自送)(HPCwire MLPerf v5.1 · AMD MLPerf 6.0 blog)。SemiAnalysis 的 InferenceMAX(2026 已更名 InferenceX v2)則是完全獨立的第三方:開源、連續(每晚重測、追蹤軟體進步)、有公開 live dashboard,直接把 GB200/GB300 NVL72、B200/B300、MI355X、MI300X 放在同一條「interactivity(tok/s/user)× cost-per-million-tokens」曲線上對撞,並輸出 token throughput、performance-per-dollar、tokens-per-megawatt 三個分母(SemiAnalysis InferenceMAX · InferenceX v2 · GitHub)。定位一句話:它是把「AMD 自報 vs 實際」之間那道縫具體量出來的那把中立尺。

為什麼重要 AI rack 是按整櫃、按三年 TCO 採購的資本財,而所有廠商的 slide(AMD 的「40% more tokens/$」「35x 推理」皆 [AMD 自報],其中 35x 是拿 MI355X 跑 FP4 比 MI300X 跑 FP8 的跨精度放大)在懂行買家面前一文不值(Tom's Hardware)。獨立 benchmark 解決的是採購前的資本風險:它把「capex 折扣」「精度切換」「利用率」全部折進同一個 matched-precision 分母,讓 hyperscaler 能在下 5 萬顆 GPU 的單前,確認「更大記憶體 → 更少加速器 → 更低 TCO」這條敘事到底在哪個 workload、哪個並發點成立。對 AMD 而言,它同時是機會也是照妖鏡:MLPerf Inference v6.0(2026-04)顯示 MI355X 在 Llama 2-70B Interactive 達 B200 的 119%、GPT-OSS-120B Server 達 115%、單集群破 100 萬 tokens/秒(StorageReview · HPCwire)——這是 AMD 開放故事第一次由中立裁判蓋章。

為何比 NVIDIA 有競爭力 獨立 benchmark 是 AMD 開放軟體故事的裁判,原因是它把戰場從 NVIDIA 的主場(CUDA 生態成熟度、廠商 demo)搬到中立場地,而 AMD 的開放特性剛好在這裡才兌現價值:(1) 開放 vs 專有——ROCm 開源、vLLM/SGLang 原生支援,InferenceX 這種「每晚重測」的連續 benchmark 能即時捕捉 ROCm 的軟體進步(SemiAnalysis 自承 2025-10 起 ROCm bug 頻率已低「數個數量級」),把 AMD 從 2024 年「開箱不可用」的舊印象裡救出來(SemiAnalysis on X);(2) 容量——288 GB HBM3E vs B200 的 180–192 GB,在獨立測試裡具體表現為「高並發同精度(60+ tok/s/user、MTP off、FP8 對 FP8)MI355X 每 token 成本反而低於 GB300 NVL72」(InferenceX GLM 5/5.1 對比);(3) 成本/多廠商——獨立 benchmark 用 perf-per-dollar 與 tokens-per-megawatt 而非峰值算力計分,讓「更少 GPU + DLC 省電」的多廠商開放櫃能在分母上贏,而不必在 NVIDIA 最強的單卡算力上對撞。但必須誠實:同一份 InferenceX 也顯示 GB300 NVL72 在低到中並發大幅領先(GLM 5/5.1 @ 41 tok/s/user:$0.23 vs MI355X $0.85,NVIDIA cost-efficient 達 265%),舊 SemiAnalysis 測試中 MI355X 未在每百萬 token 成本整體贏過 B200、一項 AMD perf/$ 低延遲宣稱在本專案驗證被 refuted(0-3)(SemiAnalysis inference benchmark)。結論:獨立 benchmark 讓 AMD「有機會贏、且贏在特定 workload」,不是「全面勝出」——這種有分寸的可信度,正是對抗廠商自報數字的武器。

NVIDIA 對應產品 benchmark 不是「產品」,NVIDIA 的對應是兩層——對外它有自己的 vendor benchmark(developer.nvidia.com 的 LLM inference cost 部落格、TensorRT-LLM 效能宣稱,性質等同 AMD 自報),對內它更擅長反客為主地擁抱同一個中立裁判:NVIDIA 官方大力行銷「NVIDIA Blackwell Leads on SemiAnalysis InferenceMAX」與 MLPerf 掃榜,且 Blackwell 在 InferenceMAX v1 幾乎橫掃、宣稱 cost-per-token 較前代降 15x(NVIDIA InferenceMAX blog)。一句話比較:同一位裁判、NVIDIA 也是選手且目前多數項目仍領先——這恰恰證明 MLPerf/InferenceX 是中立的(不是 AMD 的主場),所以 AMD 只要在特定 workload 於此蓋章勝出,說服力遠高於任何自家 slide。

參考設計(Reference Design)

是什麼 「參考設計(Reference Design)」是晶片商把整座 AI 機櫃當成一張「藍圖」交付給 OEM/ODM 的做法——不只給 GPU,而是把 CPU、GPU、DPU/NIC、互連拓撲、供電匯流排(busbar)、液冷歧管(manifold)、機構尺寸與韌體堆疊全部規範好,OEM 依此「照圖出貨」並可再客製。AMD 的具體載體是 "Helios" 機櫃:它建構在 Meta 於 OCP 2025 提交的 Open Rack Wide(ORW) 開放藍圖上,並符合 OCP、DC-MHS、UALink、Ultra Ethernet(UEC)等開放標準;AMD 明言 Helios「以 reference design 形式釋出給 OEM、ODM 與 hyperscaler,讓他們快速採用、延伸與客製,縮短部署時間、提升互通性」。定位上,參考設計是「把最難的系統整合工作前置做完」的槓桿:晶片商吃下電、熱、互連的架構風險,OEM 專注在製造良率、上市速度與差異化(如冷卻)。單櫃規格為 72 顆 MI450、FP8 up to 1.4 exaFLOPS、FP4 2.9 exaFLOPS、31 TB HBM4、1.4 PB/s 聚合頻寬(AMD 自報),量產排程 2H 2026。出處:AMD Helios/OCP blog · AMD IR PR · Next Platform 2H2026

為什麼重要 AI rack 的難點已從「單顆 GPU 多快」變成「整櫃 72 顆 GPU 如何在 ~100–150 kW 高功率下互連、供電、散熱且開機即穩定運轉」——這是系統整合問題,每家 OEM 各自從零開發要 12–18 個月且互不相容。參考設計一次解決三件事:(1) 把 scale-up 互連拓撲(UALink)、scale-out 網路(Ultra Ethernet)、供電與液冷全部標準化,消除 OEM 的架構試錯;(2) 讓「多家 OEM 同時、快速跟進」成為可能,因為大家照同一張 ORW 藍圖出貨,客戶跨廠商採購可互換;(3) 把晶片商的 roadmap 節奏(MI450→MI500 年更)直接綁進機櫃,OEM 換代不必重畫整櫃。對搶 socket 而言,參考設計等於把「一顆 GPU 的採用決策」升級成「一整櫃、含後續數代的採用決策」——鎖定的量體與黏性都高一個數量級。

為何比 NVIDIA 有競爭力 競爭邏輯是「開放 vs 專有」。NVIDIA 的機櫃級答案是 NVL72,本質是 NVIDIA 定義、以 NVLink/NVSwitch 專有互連鎖死的整櫃方案——OEM 只能在 NVIDIA 畫好的框內做少量客製,議價與差異化空間窄。AMD 走相反路線:把 Helios「捐」進 OCP 生態(建構於 Meta 的 ORW 開放規格),用 UALink + Ultra Ethernet 兩個開放互連取代 NVLink,任何 OEM/ODM 都能取用、延伸、混搭多廠商零件。三個具體優勢:(1) 容量——MI450 為 432 GB HBM4(AMD 自報),對記憶體受限的大模型/MoE inference 是「更少加速器裝更大模型」的 TCO 槓桿;(2) 成本——開放標準把機櫃「輸入」商品化,壓低整合成本並避免單一供應商溢價;(3) 多廠商——同一藍圖下 HPE、Dell、Lenovo、Supermicro、ODM 可平行供貨,客戶不被鎖死,反而放大採用速度。風險誠實面:ROCm-vs-CUDA 的實戰成熟度仍是雙向未定的公開問題,AMD 效能/TCO 數字皆為 AMD 自報未經第三方驗證(推測:開放陣營要贏,關鍵不在硬體藍圖而在軟體能否真正無痛遷移)。

NVIDIA 對應產品 對應的是 NVIDIA MGX(模組化參考架構)加 NVL72(整櫃參考設計):MGX 同樣讓 OEM/ODM 快速跟進,NVIDIA 自報可砍開發成本達 3/4、開發時程縮至約六個月,已被 ASUS、Gigabyte、QCT、Pegatron、Supermicro 等 200+ 夥伴採用,支援 Blackwell/Rubin(NVIDIA MGX · DCD)。一句話比較:MGX/NVL72 是「NVIDIA 自家主導、圍繞 NVLink 專有互連的模組化參考設計」,採用門檻低但生態綁定深;AMD Helios 是「捐進 OCP、以 UALink/UEC 開放互連的參考設計」,賣點是多廠商互換與不鎖定——同樣要 socket,一個靠生態黏性、一個靠開放與記憶體容量。
